ABS WEBSITE — TECHNICAL CONTENT NAMING
=======================================

1. GLOBAL APPLICATION STRUCTURE
-------------------------------

AppShell
  Main application wrapper that contains the complete website.

GlobalHeader
  Fixed header container for the site-wide navigation.

PrimaryNavigation
  Main navigation menu containing Home, Service, Expertise, Client, and Team.

ScrollContainer
  Main scrollable container with vertical scroll snapping enabled.

MainContent
  Primary page content rendered inside the scroll container.

SectionBlock
  Reusable full-screen section wrapper shared by all content sections.

GlobalFooter
  Final full-screen footer section.

Semantic HTML mapping:

<header>  = GlobalHeader
<nav>     = PrimaryNavigation
<main>    = ScrollContainer / MainContent
<section> = SectionBlock
<footer>  = GlobalFooter

3. COMMON SECTION ARCHITECTURE
------------------------------

Every main section uses the following technical structure:

[SectionName]Section
├── [SectionName]PrimaryContentPanel
│   ├── SectionIndex
│   ├── SectionLabel
│   ├── SectionTitle
│   ├── SectionDescription
│   └── SectionActionGroup (optional)
└── [SectionName]InteractionPanel

Important terminology:

SectionIndex
  Numeric section indicator such as 01, 02, or 03.

SectionLabel
  Small uppercase contextual label above the section title.
  This is the technical replacement for the term "eyebrow".

SectionTitle
  Primary heading for the section.

SectionDescription
  Supporting explanatory text below the title.

SectionActionGroup
  Group of one or more actions or buttons associated with the section.

PrimaryContentPanel
  Left-side primary content panel containing section labels, headings,
  descriptions, metrics, and actions.

InteractionPanel
  Right-side visual or interactive panel reserved for visual systems,
  animations, data visualizations, or future Three.js Canvas content.

InteractionPlaceholder
  Reusable dummy visual used until a section receives its final interaction.

10. VISUAL PANEL TERMINOLOGY
----------------------------

Visual panel terminology should use InteractionPanel rather than generic
names such as image, box, or placeholder.

Recommended names:

HeroInteractionPanel
ServiceInteractionPanel
ExpertiseInteractionPanel
ClientInteractionPanel
TeamInteractionPanel

Future Three.js replacements:

HeroCanvas
ServiceCanvas
ExpertiseCanvas
ClientCanvas
TeamCanvas

These Canvas components can replace the current InteractionPanel visual
implementations without changing the section layout.


11. SERVICE CONTENT SLIDER ARCHITECTURE
---------------------------------------

The Service section uses three content slides. If the Service section content
changes through slides, use the term ServiceContentSlider instead of a static
ServicePrimaryContentPanel.

ServiceSection
├── ServiceContentSlider
│   ├── ServiceTitleFrame
│   │   └── ServiceSectionTitle
│   ├── ServiceDescriptionFrame
│   │   └── ServiceSectionDescription (conditional)
│   ├── ServiceFeatureFrame
│   │   └── ServiceFeatureList
│   │   └── ServiceSlideFeature
│   │       ├── ServiceSlideIcon
│   │       └── ServiceSlideFeatureContent
│   ├── ServiceSliderControls
│   │   ├── ServicePreviousButton
│   │   └── ServiceNextButton
│   └── ServiceSlideIndicator
└── ServiceInteractionPanel

Recommended technical names:

ServiceContentSlider
  Interactive slider containing the service content.

ServiceSlideFeature
  One individual feature item in the active service slide.

ServiceSlideIcon
  Icon representing an individual service feature.

ServiceSlideFeatureContent
  Text content for an individual service feature.

ServiceSectionTitle
  Main title displayed above the service slider.

ServiceSectionDescription
  Supporting description displayed below the service title.

ServiceTitleFrame
  Fixed responsive area that keeps service titles at a stable height.

ServiceDescriptionFrame
  Fixed responsive area that keeps features aligned when a description is absent.

ServiceFeatureFrame
  Fixed responsive area that keeps navigation aligned across different feature counts.

ServiceSliderControls
  Container for previous and next slide controls.

ServicePreviousButton
  Control that moves to the previous service slide.

ServiceNextButton
  Control that moves to the next service slide.

ServiceSlideIndicator
  Pagination indicator showing the active slide and total slides.

Example technical markup:

<div data-component="ServiceContentSlider">
  <h2 data-element="ServiceSectionTitle"></h2>
  <p data-element="ServiceSectionDescription"></p>
  <ul data-component="ServiceFeatureList">
    <li data-component="ServiceSlideFeature">
      <span data-element="ServiceSlideIcon"></span>
      <span data-element="ServiceSlideFeatureContent"></span>
    </li>
  </ul>
  <div data-component="ServiceSliderControls">
    <button data-action="ServicePreviousButton"></button>
    <button data-action="ServiceNextButton"></button>
  </div>
  <div data-element="ServiceSlideIndicator"></div>
</div>

14. NAMING RULES
----------------

1. Use PascalCase for React component names.
2. Use descriptive section prefixes such as Hero, Service, Expertise,
   Client, Team, and Footer.
3. Use PrimaryContentPanel for the main text and action area of a section.
4. Use InteractionPanel for visual or interactive right-side areas.
5. Use SectionLabel instead of eyebrow.
6. Use SectionTitle for main section headings.
7. Use SectionDescription for supporting descriptions.
8. Use ActionGroup for groups of buttons.
9. Use MetricValue and MetricLabel for statistics.
10. Use FooterLegalBar for copyright and legal links.
11. Use Canvas suffix for future Three.js components.
